# Порядок работы четырёх агентов

Нормативный протокол находится в [AGENT_CONTRACT.md](AGENT_CONTRACT.md); начальная инструкция — [AGENTS.md](../AGENTS.md). Этот файл не содержит второй версии правил.

1. Прочитать назначенный Issue, зависимости, продуктовые контракты и связанные PR.
2. Отправить START, проверить пересечения, работать в своей ветке и рабочей копии.
3. До несовместимого изменения отправить CONTRACT_CHANGE; при внешнем препятствии — BLOCKED с адресатом и требуемым действием.
4. Выполнить пять критериев, приложить реальные проверки и отправить READY_FOR_REVIEW с base/head SHA.
5. Любой участник, не участвовавший в реализации PR, проверяет его своим агентом в отдельной сессии и может дать человеческое одобрение. Указанный в задаче ревьюер — рекомендуемый первый адресат; ждать его не требуется. Фактическое имя фиксируется в отчёте.
6. Исправить подтверждённые находки, объяснить отклонённые и обновить необходимые проверки.
7. Merge — только по отдельной команде человека. HANDOFF отличает доступную ветку от принятого main.

Начать с [очереди](ISSUE_INDEX.md). Один основной Issue In progress на человека. GitHub сам не запускает локальных агентов.
