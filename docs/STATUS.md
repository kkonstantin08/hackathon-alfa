## Первый этап — вклад каждого в данные

| Задача | Участник | Первый результат | Зависимость |
| --- | --- | --- | --- |
| Профили компаний | A, имя не назначено | Проверенные поля, загрузчик и контрастные профили | CSV компаний |
| Платежи и связи | B, имя не назначено | Проверка ID и простые агрегаты для профилей | CSV платежей/связей; затем общие компании с A |
| Аналитика банка | C, имя не назначено | Текст, фрагменты с датами/страницами и поиск | Девять PDF |
| Новости | D, имя не назначено | Корпус с источниками, сборщик, дедупликация и отложенная часть | Доступные внешние источники |
| Проверочные примеры | E, имя не назначено | Пары «компания × новость», основания и общий вход/выход пробного запуска | Сначала формат и небольшие примеры; затем результаты A–D |

Полные задания и способ совместной сборки — в [ROLES.md](ROLES.md). Работу начинают параллельно после краткого согласования форматов. Эти задачи ещё не созданы отдельными Issues и не считаются начатыми.

Общая контрольная точка: повторяемый запуск «профиль + новость + аналитика → проверяемый разбор» с вкладом всех пяти, затем другая компания и новая новость. Достаточно скрипта/ноутбука. После проверки распределить профильные задачи приложения; UI, полный API и деплой — следующий этап.

## Блокеры и риски

- Неизвестны дедлайн, имена участников A–E и доступное время; постоянные специальности пока не нужны для распределения старта.
- Не проверены полнота и различия профилей; убедительность персонализации пока не доказана.
- Нет подтверждённой конфигурации API и среды показа; ключ отключается после приёма решений.
- Сохранённые ответы не доказывают качество на новых новостях или работу живого агента.

Ближайшее действие — распределить пять задач по людям и назначить время сборки первых примеров. Время и координатора определяет команда. Зелёный CI каркаса не означает готовность анализатора.
