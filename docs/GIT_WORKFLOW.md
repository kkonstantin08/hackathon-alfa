# Ветки и PR

Одна небольшая задача обычно соответствует одной ветке и одному PR. Новые ветки по умолчанию: codex/<issue-number>-<short-topic>; параллельные агенты используют разные рабочие копии.

Коммиты и заголовки PR — Conventional Commits. Только свои изменения, без прямого push в main. Принятые интерфейсы меняются через CONTRACT_CHANGE и проверку потребителей.

PR содержит связанный Issue, доказательства пяти критериев, проверенные base/head SHA, реальные команды, ограничения и имя независимого ревьюера. Соавтор не проверяет свой PR. Полный протокол: [AGENT_CONTRACT.md](AGENT_CONTRACT.md).

Одного одобрения от любого участника команды, не участвовавшего в реализации PR, достаточно при выполнении остальных условий. Ревьюер в Issue — рекомендуемый первый адресат; его можно заменить без отдельного разрешения, указав фактическое имя в отчёте.

Перед merge: актуальный зелёный обязательный CI, завершённое независимое ревью, устранённые P0/P1, явные человеческие решения по P2, одобрение другого человека и отдельная команда merge. После изменения кода старое одобрение не подтверждает новую версию.

Closes #... используется только для полностью закрываемого результата; для частичного вклада — Refs #... . HANDOFF отличает принятую версию от доступной только в ветке.

Аварийные правила не разрешают автономный merge или обход обязательного CI. Настоящие ограничения GitHub проверяет владелец в ADMIN-01.
