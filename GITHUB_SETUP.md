# Настройка GitHub владельцем

Инструкции не включают защиту main автоматически. ADMIN-01 выполняет владелец с admin-доступом; у автора этого PR есть push/triage, но нет admin.

1. Проверить реальные GitHub-аккаунты четырёх участников. Имена в Issues не подменять выдуманными Assignees и CODEOWNERS.
2. Требовать PR и минимум одно одобрение другого человека; включить отзыв устаревших одобрений либо эквивалентный контроль актуального изменения.
3. После первого запуска назначить обязательными существующие jobs foundation и application workflow CI. Проверить блокировку красного и отсутствующего CI.
4. Запретить force-push и удаление main; административный bypass не использовать как обычный путь.
5. Подтвердить настройки и их действие на проверочном PR; при отсутствии прав оставить ADMIN-01 Blocked.

AI-отчёт не является GitHub Approval и не доказывает независимость сессии. Одобрение даёт другой человек; отдельная команда merge остаётся обязательной.

CI этого PR: foundation — исходные проверки каркаса; application — uv.lock, ruff и pytest с контрактами и mock API. Нужных модельных ключей нет. Проверки не исполняют код PR с токенами записи или deploy-секретами. Полнота и контролируемая отрицательная проверка остаются в D-06.

У Issue одна актуальная status:* метка. Done — закрытие после принятого результата, не после создания PR. role:* обозначает область, а не аккаунт.

Deployment не включён; шаблон templates остаётся неактивным. Внешний AI-бот и автоматическое пробуждение локальных агентов не настроены.
