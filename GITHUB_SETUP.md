# Настройка GitHub владельцем

Инструкции не включают защиту main автоматически. ADMIN-01 выполняет владелец с admin-доступом; у автора этого PR есть push/triage, но нет admin.

1. Проверить реальные GitHub-аккаунты четырёх участников. Имена в Issues не подменять выдуманными Assignees и CODEOWNERS.
2. Требовать PR и минимум одно одобрение любого другого участника команды с правами, позволяющими засчитать Approval. Не ограничивать одобрение конкретным ревьюером, CODEOWNERS или отдельной командой; включить отзыв устаревших одобрений либо эквивалентный контроль актуального изменения. Автор не одобряет свой PR; участие соисполнителей проверяется дополнительно по отчёту и истории изменений.
3. После первого запуска назначить обязательными существующие jobs foundation и application workflow CI. Проверить блокировку красного и отсутствующего CI.
4. Запретить force-push и удаление main; административный bypass не использовать как обычный путь.
5. Подтвердить настройки и их действие на проверочном PR. Если начатую административную работу остановило отсутствие прав, зафиксировать Blocked с конкретным действием владельца; обычное ожидание очереди обозначать Backlog.

AI-отчёт не является GitHub Approval и не доказывает независимость сессии. Одобрение даёт другой человек; отдельная команда merge остаётся обязательной.

Имена ревьюеров в Issues — рекомендации для распределения нагрузки. Любой из четырёх участников, не участвовавший в реализации PR, может взять проверку и одобрение без дополнительного разрешения; фактическое имя фиксируется в отчёте. Для зачёта одобрения владелец проверяет права реальных аккаунтов всех четырёх участников. GitHub запрещает автору одобрять собственный PR; запрет для остальных соисполнителей дополнительно является командным правилом.

При чтении действующих правил main 24.10.2026 подтверждены: одно обязательное одобрение, сброс устаревших одобрений после push, отсутствие обязательного конкретного ревьюера и CODEOWNERS, обязательные foundation и application, запрет force-push и удаления main. Это чтение конфигурации; проверка прав всех четырёх аккаунтов и контролируемых отрицательных сценариев остаётся в ADMIN-01.

CI этого PR: foundation — исходные проверки каркаса; application — uv.lock, ruff и pytest с контрактами и mock API. Нужных модельных ключей нет. Проверки не исполняют код PR с токенами записи или deploy-секретами. Полнота и контролируемая отрицательная проверка остаются в D-06.

У Issue одна актуальная status:* метка. Done — закрытие после принятого результата, не после создания PR. role:* обозначает область, а не аккаунт.

Deployment не включён; шаблон templates остаётся неактивным. Внешний AI-бот и автоматическое пробуждение локальных агентов не настроены.
